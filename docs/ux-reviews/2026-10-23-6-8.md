# Child UX review: ages 6-8
Reviewed: Home screen Practice card, 7 note buttons in a 4+3 grid. Sources: ui/home_screen.py (_build_practice_card), ui/theme.py (QPushButton#note), web/css/app.css (.note-choices, .note-choice, phone block), web/js/ui/screens.js, web/index.html, docs/design/Home.dc.html, docs/SPECIFICATIONS.md. Date: 2026-10-23.
Evidence limits: The app could not be run and no screenshots exist, so everything below comes from code and docs. Real pixel widths, text clipping and wrapping are unverified. Home.dc.html contains the Practice card text but no note-button markup that I could find, so the mockup does not show the 7-note grid (unverified beyond that search). The spec (line 79) already says "pick one of Do, Ré, Mi, Fa, Sol, La, Si", so the change brings the build closer to the spec and does not conflict with it.

## Age 6-8
**Verdict:** The child sees a friendly row of Do-Re-Mi buttons, picks one, and taps the big "Start practice". It feels familiar and easy, but the selected state is weak on desktop and the grid may feel cramped on a phone.

**What works**
- Do, Ré, Mi, Fa, Sol, La, Si is the song the child already knows from school. Left to right, top to bottom, it reads like a scale, so no explanation is needed.
- Buttons are large: at least 100px high on desktop, 84 to 120px on the web, with a 12px gap. That is easy for a 6-8 hand and tolerates a slightly off tap.
- "Do" is preselected (desktop `buttons[0].setChecked(True)`, web `selected = practiceNotes[0]`). The child can press Start immediately, so there is one obvious next action.
- The big solfege name (42px desktop, up to 2.7rem web) is readable from arm's length. It uses words the child knows, not "C4".
- The web version adds a checkmark badge to the selected note, so selection is not shown by color alone.
- No failure or negative text. The card copy is short: "Pick one note and play it 10 times." and "Hold the note steady for 3 seconds to score a point."
- Accessible names ("Do (C4)") and radio roles on the web.

**Problems**
1. [Major] Home, Practice card, desktop - "Which one did I pick? They all look white." The selected note differs only by a pale blue fill and a border color change (`QPushButton#note:checked`, same 4px border). There is no checkmark or shape change as on the web. A child who takes things literally, or one with color-vision deficiency, may press Start with the wrong note. -> Fix: add a non-color cue to the checked state in Qt to match the web, such as a check badge in the corner or a thicker border plus a "✓" in the sub-label. This follows the "not color alone" rule.
2. [Major] Home, Practice card, phone web (max-width 600px) - "The buttons are squashed and the tick sits on my word." The phone block keeps 4 columns. On a roughly 360px phone, after page and card padding each button is only about 60px wide. "Sol" at 2.1rem (about 34px) will be tight. The 22px tick badge sits at top 5px, right 5px inside a 60px-wide cell and may overlap the text. The row height of 84px is fine; the width is the problem. Real widths are unverified. -> Fix: keep the 4+3 layout, but reduce the phone gap and card padding, or drop the solfege font a step, and verify at 320 and 360px. Check that the tick does not overlap "Sol" and "Mi".
3. [Minor] Home, Practice card, desktop - "Is the big word cut off?" Two cards sit side by side, so each note cell is probably about 100px wide. "Sol" at display size 42 plus the 20px letter line may clip or push the layout, and the card must also fit the header, hint, Start button and difficulty switch in the window height. Unverified. -> Fix: have someone run the app at the minimum window size and check the grid, the Start button and the Adventure card for clipping or scrolling. Make the font size follow the cell width if needed.
4. [Minor] Home, Practice card - "What is C4?" The small grey "C4" under each solfege name means nothing to a 6-8 child. It is muted, so it does little harm, but it adds clutter to every button. -> Fix: keep it for the teacher or parent, but make it smaller or lighter, or show it only in Settings or on hover. Keep the aria-label.
5. [Minor] Home, Practice card, 4+3 grid - "Why is Si all alone, with an empty spot next to it?" The last row has three buttons and a gap on the right. It is harmless, but it looks unfinished, and the Si row sits on the left, away from the Start button. -> Fix: center the last row, or let Si span the empty column. This is optional polish.
6. [Minor] Home, Practice card - "I picked Si and I can't do it. I keep missing." All 7 notes are offered with no hint about which are easier. A child who jumps to the top note on a horn may miss repeatedly. Practice has no failure state and no stars (FR-16, FR-24), so this is not a blocker, but the 6-8 child gets discouraged quickly. -> Fix: no layout change needed. Keep "Do" as the default, and make sure the Practice screen's flat/sharp hints say higher or lower. Do not remove notes, since the spec lists all seven.
7. [Minor] Home, web - Keyboard: the note buttons are `role="radio"` inside a `radiogroup`. Whether arrow keys move between them is unverified in screens.js, and radio semantics normally expect it. -> Fix: add arrow-key navigation, or use plain toggle buttons.

**Would this child come back tomorrow?** Yes. Choosing a note by its Do-Re-Mi name is easy to do and feels grown-up. The risk is only an unclear selected state and a squeezed phone layout.

## Cross-age summary
- Only age 6-8 was reviewed this time. The ranked issues are: (1) the non-color selected state in Qt, which also matters for 3-5 and for color-blind users of any age; (2) the narrow 4-column phone layout; (3) unverified desktop clipping.
- Possible conflict for other bands: the "C4" label is noise for 3-5 and 6-8 but useful for 12-15. Recommended resolution: keep it small and muted.
- Spec: no conflict. The spec (line 79) calls for seven notes, and the 4+3 grid matches it. FR-16 and FR-24 (no failure, no stars in Practice) are respected. Home.dc.html does not show the note grid, so the design doc should be updated to include it (docs first, then code).
