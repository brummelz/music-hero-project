# Child UX review: web version, ages 6-8
Reviewed: Horn Hero web build (branch `html-version`), 33 headless-Chrome screenshots with `?sim` (desktop 1280x800, tablet portrait 820x1180, phone 390x844 at 2x), plus `web/index.html`, `web/css/app.css`, `web/js/ui/*.js`, `web/js/app.js`, `web/js/core/feedback.js`; spec FR-16, FR-18, NFR-01, §6.1; earlier desktop review `2026-10-10-6-8.md`. Date 2026-10-11.
Evidence limits: static screenshots only. No real microphone or horn (the simulator never wobbles). Sounds (chime, "hear the note" button) not heard. The microphone-permission prompt and the refused-permission help panel (`#mic-help`) were NOT captured, so that flow is judged from code only. The practice-complete screen ("You did it!") and the hold-to-open ring/hint toast were not captured: unverified. Touch behaviour is inferred from CSS and JS, not tested on a touch device. Tablet game screens (shots 3-9) pre-date the portrait staff-size fix, so the small staff seen there is not counted as a finding. Phone pixel sizes below are CSS px (screenshot px / 2). Screenshots 10 and 11 were read for phone and tablet only for settings; desktop 3-5, 8, 10, 11 and tablet 3, 5, 7, 8, 10 were not individually opened, since they share layout with the ones that were.

## Age 6-8
**Verdict:** On a tablet or computer the web app feels like the desktop one: friendly cover, one clear Do/Ré/Mi choice, a calm waiting screen and clear flat / in tune / sharp feedback. On a phone the very first button is thin and tiny, and the "I did it!" moments are still small, so a child gets a good start but a modest reward.

**Earlier desktop findings (2026-10-10-6-8.md): status**
- Fixed or improved: the home screen now shows a mic-friendly "Hold the note steady for 3 seconds to score a point." in plain words (earlier Minor 7 partly). The settings gear is now hold-to-open with a filling ring and a hint on a short tap (earlier Major 3, partly fixed: see new problem 4). Messages now have a "So close! Start the hold again." state so a reset is never silent (relates to earlier Major 5).
- Remain unchanged: tiny reward on a scored point (earlier Major 1: still a small star in a white circle, "Great job! +1 point!", one dot fills; on phone the dots are hidden entirely); flat level/practice end screens (earlier Major 2: level summary is still stars on a plain white card, no character); literal wording "Lift the note up" / "Relax and come down" (earlier Major 4, wording is in FR-18 so spec-owner decision); "Written pitch · Horn in F" and "Target note" captions (earlier Minor 7); "2.0 / 3.0 s" decimal read-out (earlier Minor 8); saturated red outer zones (earlier Minor 6); home has no character (earlier Minor 10); "Try again to collect all 3 stars" wording is now "Great playing! You had N restarts. Keep it to X or fewer to win all 3 stars." (code only, see problem 9). Message flicker (earlier Major 5) cannot be judged with the non-wobbling simulator: unverified.

**What works**
- Cover (all sizes): the same friendly boy, mascots and floating Do / Ré / Mi bubbles; one big purple "Start Game!". Text on it is large and high contrast on tablet and desktop.
- Home (phone 2, 10): everything is one column, big and readable. Do / Ré / Mi tiles are about 105 x 95 CSS px with solfege first and the letter second. "Start practice" is a full-width pill. The current level has a "Play" pill; locked levels are dashed with a lock and the word "Locked", so it is not color alone. Earned stars show as real stars in the level row (phone 10).
- Game (all sizes): "DO / C" is huge; the silence state is calm ("Take a breath and play your Do!", music-note icon, "Listening...", dashed pulsing ring). Flat, in tune and sharp each change marker position, pill ("Flat", "In tune", "Sharp"), arrow or check icon, and message, so color is never the only cue (phone 4, 5, 6).
- Hold ring around the note fills green and the notehead turns green (phone 6, tablet 6): a literal "it is filling" cue that is still readable on a phone.
- Phone game screen: back arrow, gear and score pill are 48 CSS px round or pill targets, well apart from the feedback bar; the note label drops to its own row, which keeps "DO / C" large.
- Level complete (phone 9): three large gold stars, "Amazing! All 3 stars", a green "Level 2 unlocked" chip and an obvious primary "Next level". Empty stars are dashed, not crossed out (FR-23).
- Every message is short and positive; no failure wording anywhere seen (FR-16, FR-18).
- Settings dialog is clearly labelled "For grown-ups" and fits a phone as a scrolling sheet (phone 11).

**Problems**
1. [Major] Cover on a phone (phone-1-cover) - "I see the picture but where do I press? The button is a thin purple pill." The cover is a fixed-ratio picture (1600x1195) scaled to screen width, with the button as a percentage overlay. On a 390 px wide phone held upright, the button is about 140 x 29 CSS px with about 12 px text (`.cover-button` height 9.9% of the frame, font 4.2cqh), below the project's own 48 px touch size and below the 44 px norm. The whole picture is also only about 291 px tall in an 844 px tall screen, with empty pale blue above and below, so everything looks small. A 6-8 child will miss it, tap beside it and (because the button also triggers the microphone prompt) think nothing happened. -> Fix: on narrow or portrait screens make the Start button a real element outside the picture, full width or at least 260 x 64 CSS px, with 1.4 rem+ text, placed under the picture (or add a larger transparent tap area around the pill). Alternatively use a portrait cover art crop. Keep the label "Start Game!".
2. [Major] Cover on every device - "I pressed Start and a grown-up box asked about the microphone; what is that?" Spec §6.1 makes "Start Game!" also ask for microphone permission. The child sees "Warming up the horn..." and then a browser prompt (not captured) written for adults. If they miss it or tap Block, the child is stuck at the cover until a grown-up helps. The help panel exists (`#mic-help`, "Let Horn Hero hear you", "Try again") and is calm and has no failure look, which is good, but its second paragraph ("open the browser's site settings (the lock icon next to the address)") is adult text and is not tied to a picture. -> Fix: no behaviour change needed (spec §6.1 stays). Add a short pre-prompt line under or on the cover button for grown-ups ("Tap Start, then Allow the microphone"), show a big microphone-with-ear icon beside the help panel title, and put the lock-icon instruction in a small "Ask a grown-up" block so the child sees only "Try again". Capture and review the real prompt flow once on iOS Safari and Android Chrome (unverified here).
3. [Major] Scored point on every size, worst on phone (phone-7-point) - "Did I get it? The top right says 1 / 10 now." On a phone the score pill hides the dots (`.score-pill .slots { display: none }`), so a point is only the text "1 / 10", a small star in a white circle in the feedback bar, and "Great job! +1 point!". The chime is unverified. The child works for three seconds and gets the smallest reward on the smallest screen. Same finding as earlier Major 1, now stronger. -> Fix: on a point, pop a large star (about 120 px) over the staff card for about 1 s and fly it to the score pill; on phone show a compact row of stars (or a single filling star) in the feedback bar instead of hiding the dots. Keep the celebrate timing and volume setting, honour reduced motion.
4. [Major] Settings gear, touch (all game screens and home) - "That round gear next to my score; I'll press it." The gear is hold-to-open, which is a real improvement over the desktop one-tap. But: (a) the hold is only 1 s (`HOLD_MS = 1000`), a 6-8 child who rests a finger on it, or a child who mashes, can open it; (b) the gear is the same 48 CSS px size, outline and weight as the Back arrow and sits right beside the score pill, so it looks like a normal game button; (c) on a short tap the hint "Hold to open settings" is a toast (not captured, unverified) that a child may not read, and the ring starting to fill invites them to keep holding; (d) opening it mid-practice pauses the game and lets a child change tolerance, hold mode and "Reset progress…" (the reset has a confirm with a Reset / Cancel step, which helps). -> Fix: raise the hold to about 2 s (as a named config constant, not hard-coded in the widget), make the gear smaller and lower-contrast than Back, and move it out of the game top bar (home-only) unless the spec requires it there (not found in §6.1 or Screen 2; confirm). If it stays, show the "For a grown-up: hold for 2 seconds" hint as text beside the ring rather than a vanishing toast.
5. [Major] Level and practice end screens (phone-9, tablet-9, desktop-9) - "Three stars, OK... that's it?" Better than a plain list, but still stars on a big empty white card with small buttons, no mascot, no star burst, and the practice version (not captured, unverified) shows "You did it!" plus a points row and no stars (FR-24). On the phone the card is mostly white space (about 480 CSS px of empty card above and below the content) and the buttons wrap to two rows with "Next level" below "Home / Play again", at 48 CSS px height but with narrow widths (about 95 x 48 CSS px for Home). -> Fix: add the boy-with-horn art from the cover and a short star burst; on phone stack the buttons full width with "Next level" first and largest; for practice show 10 small stars or one large star instead of the dot row. Keep text to one line.
6. [Major] Home on a phone and tablet (phone-2, tablet-2) - "Which do I press, Practice or Adventure?" Practice sits first and bigger on phone (Practice card fills the first screen) while Adventure with its stars is below the fold (needs a scroll to see "Five-note scale" and more). A first-time child will start with Practice (10 repeats of one note, no stars) and miss the star adventure that motivates this age. The "Play" pill and the lone current level are good once seen. -> Fix: for a first-time profile put Adventure first on phone, or mark Adventure "Start here" with a star; keep Practice for returning children. Pair each card with a larger icon-only cue (flag, note).
7. [Major, unverified live] Practice screen, message flicker with a real horn (all sizes) - Same as earlier Major 5. A beginner's horn wobbles; the simulator does not, so the web version still has no evidence about whether the bar and sentence flip several times a second. -> Fix: add a minimum display time for a message (about 400 ms, config constant) and test with a wobbling tone.
8. [Minor] Game screen, phone and tablet (phone-3 to 8, tablet-4) - "Written pitch · Horn in F", "TARGET NOTE" and "Hold for 3 seconds" are small (about 13 CSS px on phone, `.staff-captions` 0.8 rem), use adult words, and fall in a corner. Earlier Minor 7, still there. -> Fix: "PLAY THIS NOTE", hide the "Written pitch · Horn in F" caption for this age (grown-up info), enlarge "Hold for 3 seconds" with a timer icon.
9. [Minor] Level summary message (phone-9 for 3 stars; code `starReason`) - 3 stars reads "Amazing! All 3 stars (0 restarts)." The "(0 restarts)" is jargon and the child does not know what a restart is. For fewer stars the text is "Great playing! You had 2 restarts. Keep it to X or fewer to win all 3 stars." (code only, not captured), which is long for a 6-8 reader and mentions what was missed. -> Fix: 3 stars: "Amazing! All 3 stars!" Fewer: "Great playing! Can you get 3 stars next time?" Keep the restart count for grown-ups or in small text. Wording of star rules is in FR-22/FR-23; confirm with the spec owner.
10. [Minor] Hold read-out (phone-6) - "2.0 / 3.0 s" is a decimal fraction. Earlier Minor 8. -> Fix: whole seconds 1, 2, 3 or hide at this age; the ring already shows progress.
11. [Minor] Gauge outer zones (phone-4/5) - saturated red ends read as "wrong". Earlier Minor 6. Position, pill and arrow already carry the meaning. -> Fix: soften to coral or purple.
12. [Minor] Phone landscape (code only, no screenshot, unverified) - at 500 px height or less the captions and the simulator pad are hidden; staff and gauge shrink. Check on a real phone that the staff note and ring stay at least about 90 px tall.
13. [Minor] Home on phone (phone-2) - the "Horn in F" chip is hidden on phones, which is fine, and the star total chip is clear. The home header gear is the same weight as the star chip; see problem 4.
14. [Minor] Settings on phone (phone-11) - the dialog covers nearly the whole screen and "Done" / "Reset progress…" sit below the fold (needs a scroll; not captured). A child who opens it has no obvious close. Adult text: "cents", "Sensitivity", "Live test", "Hearing". -> Fix: add a large "Done" at the top as well as the bottom and a plain-language line under "How exact the note must be" ("Easy is kinder for beginners"). Dialogs here are for adults, so the text level is acceptable.
15. [Minor] Simulator pad (all game shots) - "Simulation: Flat / In tune / Sharp" is visible in the captured `?sim` build only. Assumed hidden in the normal build (unverified): confirm, because a child would press it.

**Would this child come back tomorrow?** Maybe. The picture, Do / Ré / Mi tiles and clear in-tune feedback work well and the controls are big on a tablet. On a phone the first tap is hard to hit and the reward for a point is a text change. Fix problems 1, 3 and 5 and this moves to yes.

## Cross-age summary
Only age 6-8 was reviewed.
- Ranked, shared with other likely ages: (1) too-small rewards for a scored point and at the end (affects 6-8, likely 9-12); (2) thin or small cover Start button on phone (affects every age, and 3-5 most); (3) settings gear reachable by a child (3-5 and 6-8; teens will try to find it deliberately); (4) message flicker with a real horn.
- Conflicts: mascot art and star bursts suit 6-8 and may feel babyish for 12-15; resolve with a short, optional celebration rather than removing it.
- Spec notes: FR-16 (no failure state) holds in all captured screens. FR-18 quotes "Push a little higher" style wording, so any rewording of problem 4 in the earlier review or of "Lift the note up" needs spec-owner sign-off. §6.1 requires the cover Start to also ask for the microphone and to offer a retry without a failure state: the code follows that; problem 2 only adds supporting visuals. A gear on the game screen is not mandated by §6.1 (confirm before moving). Hold time (3 s), grace (150 ms), tolerance and the settings hold time (1 s) must stay config constants, not hard-coded.
