# Child UX review: ages 3-5 (web version)
Reviewed: Horn Hero web build on branch `html-version` (`web/`), 2026-10-11. 33 screenshots of the real app in headless Chrome with `?sim` (keyboard simulator in place of a horn), at desktop (1280x800), tablet (820x1180 portrait) and phone (780x1688 px, which is 390 CSS px at 2x device pixel ratio, inferred from the 96 px gear button being `--touch: 48px`). Plus `web/index.html`, `web/css/app.css`, `web/js/ui/*.js`, `web/js/app.js`, `web/js/core/feedback.js`, spec `docs/SPECIFICATIONS.md` (FR-16, FR-18, NFR-01, section 6.1), and the earlier desktop-app review `docs/ux-reviews/2026-10-10-3-5.md`.
Evidence limits: static screenshots only; the app was not launched by me. No real microphone or horn (keyboard simulator), so real detection, wobble, and dropout behaviour are unverified. Sounds (success chime, reference tone) were not heard. No microphone-permission prompt was captured (the browser's own prompt, and the app's refusal help panel `#mic-help`, were read in code only). The tablet game shots were taken before the "larger staff in portrait" fix, so the tablet staff size is unverified in its current state; phone shots are current. The practice-complete screen, the 1- or 2-star level summary (empty third star) and the settings dialog on tablet/desktop were not reviewed in detail. All animation and timing is inferred from code. Hold-to-open settings was read in code only (never seen operated on touch).

## Age 3-5
**Verdict:** The cover is still a lovely, inviting picture with one huge button, and the web version adds good things (a speaker button, hold-gated settings, friendlier arrows). But a 4-year-old on a phone or tablet still crosses from a cartoon world into a grown-up's tuner with no friend on screen, taps a first button that is physically small on a phone, and meets a browser permission box they cannot read.

### What works
- Cover (all sizes): one obvious action, the purple "Start Game!" pill under the boy, the smiling microphone, squirrel and rabbit. Alt text on the image describes the scene. On tablet it is ~294 x 60 px and on desktop ~385 x 78 px, easily tappable.
- Start tap is protected against mashing: the button is replaced by "Warming up the horn..." (`#cover-busy`) while the microphone starts, so a child cannot start twice.
- Fixed since the desktop review: arrow clash (earlier item 3). The Flat / Sharp pills now use the musical signs "flat" and "sharp" (`♭ Flat`, `♯ Sharp`) and only the message bar uses arrows (up arrow = play higher, down arrow = come down). One meaning per arrow. Position of the needle + highlighted pill + arrow icon + words is not colour alone.
- Fixed since the desktop review: reference tone (earlier item 6). A speaker button now sits next to the target note ("Hear the note"). It is the only part of the screen a pre-reader can use to learn what "Do" sounds like.
- Fixed since the desktop review: child can open Settings (earlier item 9). Gear now needs a press-and-hold (`HOLD_MS` = 1000 ms) with a ring that fills; a quick tap shows the hint "Hold to open settings". Settings text says "For grown-ups". The Reset progress action has an inline Reset / Cancel confirmation. A random tap cannot open it.
- Silence (phone 3) is calm: pale, dashed needle, music-note icon, blue-grey bar, "Take a breath and play your Do!". It does not look like an error.
- Hold ring (phone 6, tablet 6, desktop 6) fills clockwise in dark green and the note head goes green; good "it's working" cue that is not a number.
- Phone layout reflows well: top row Back / gear / "0 / 10", note name below, gauge and message bar full width. Nothing is cut off in the phone shots. Home note tiles (Do / Ré / Mi) are ~105 x 95 CSS px on phone: very good for little fingers, with Do pre-selected and a ~64 px "Start practice".
- Level summary stars (phone 9, desktop 9) are big and bold; the page is calm and has no failure look. "Level 1 complete!" and "Next level" are one obvious tap.
- Messages remain short and positive in `feedback.js` (FR-18 text). No "wrong", "fail", "lose" in gameplay.
- Works offline as a PWA (spec 6.1): no network error scenes for a child at home without wifi (not verified in a browser).

### Problems
1. [Major] Cover on phone (phone-1-cover) - "The button is tiny and I miss it." In portrait the cover image is scaled to the screen width, so the picture fills only about the middle third of the screen with big empty blue bands above and below; "Start Game!" is only ~140 x 28 CSS px (280 x 56 px in the 2x screenshot). That is below any 44 px touch minimum and far below what a 3-5 child with poor fine motor control needs. On tablet and desktop it is fine. Likely behaviour: taps the horn or the boy, nothing happens, hands the phone to the grown-up. -> Fix: on narrow/portrait screens render a separate large Start button below the picture, full width, at least 72 px high, instead of scaling the painted-in button position; or make the whole picture area a tap target in addition to the button. Keep the same label. (Note: the cover is a spec-sanctioned illustration with its own button; this changes layout only.)
2. [Major] Cover, Start Game also asks for the microphone (app.js `begin`, spec 6.1) - "A box popped up with words, I tapped something and now it is stuck." A 3-5 child cannot read the browser's native permission prompt (Allow / Block). A mashing finger can easily hit "Block" (or dismiss it), after which the app's `#mic-help` panel appears: all text ("Let Horn Hero hear you", "Tap Try again and choose Allow", "open the browser's site settings (the lock icon)..."), and Retry cannot undo a permanent block. The child is stuck with no picture-only way forward. The wording itself is kind (no failure state, FR-16 respected), but nothing a pre-reader can use. Likely behaviour: taps randomly, stops, waits for a grown-up. -> Fix: (a) add a picture-led screen before the prompt is triggered only if needed: the smiling microphone character with a big "ear" or sound-wave icon and a pointing hand toward the Allow button, one spoken-style line for the grown-up ("Grown-up: tap Allow"); (b) on refusal show the mic character with a big "Ask a grown-up" icon (adult-icon + lock icon) and keep the long instructions in a smaller adult-facing block; (c) make "Try again" a very large button. Do not change spec behaviour (asking at Start); only the presentation after it.
3. [Major] Game screen on all sizes, still no friend - "Where did the boy and the microphone go?" (carried over from earlier item 1). After the cover, the child never sees a character again: Home, Game, Summary have a clef, a gauge and a message bar. The microphone character is the natural listener. Likely behaviour: looks away, only plays when the adult prompts. -> Fix: place the cover's microphone (and squirrel/rabbit on the summary) in a fixed spot on the game and summary screens, driven by the same Feedback value (`data-feedback` on `#feedback` already exists): sleepy in silence, head-tilt arrows in flat/sharp, bouncing at in tune and at completion. Reuse cover assets (offline).
4. [Major] Game (all sizes), hold progress is still small and still a number - "What is the little circle?" (carried over, earlier item 2). The hold ring is ~70 CSS px on phone (140 px in the 2x shot), ~90 px on tablet, ~95 px on desktop, sitting on a note head the child cannot read, in a large mostly empty white staff card. The explanation, "Hold for 3 seconds" and "2.0 / 3.0 s", is text only. The ring is the only 3-second cue. The portrait staff fix may enlarge it on tablet (unverified). -> Fix: scale the ring with the staff card (aim for at least 25 percent of the card height) and add a large, picture-only progress cue (e.g. 3 stars or balloons that light one per second) above the message bar; show the numeric "x / 3.0 s" only in a small grown-up line. Use the hold seconds from the config value, not a hard-coded 3.
5. [Major] Game, far-zone red (phone 4, phone 5) - "Red means I did something bad." Unchanged from earlier item 4: `--red: #FF6B6B` fills the gauge ends, the active pill and the pink message bar (`--red-soft`) for flat_far and sharp_far. Words are kind and arrows carry direction, but red is the loudest object on screen at the child's point of failure. FR-16 forbids any hint of loss; this is a presentation risk, not a rule break. -> Fix: swap red for a warm non-alarming colour (soft orange or lavender) in gauge ends, pill and message bar, keeping position + arrow + words; keep green as the only "yes". Keep contrast and colour-blind pairing.
6. [Major] Game, speaker button (phone 3-7) - "What is that speaker thing?" The reference-tone button is the right idea but it is a 48 px outlined circle beside a text label, with no label, no pulse, and nothing inviting the child to press it; the silence message ("Take a breath and play your Do!") does not point to it. The tone itself (and its echo-guard of ~0.3 s plus a hold reset) was not heard or tested by me. A pre-reader may never discover it. -> Fix: make it the biggest and friendliest button on the game screen (a large coloured speaker/ear button, at least 72 px, gently pulsing in silence on the first prompt of each note), and let it also play automatically once when a new target note appears, under the volume setting. Flag to the product owner as a possible requirement: it is not in the spec text I read.
7. [Major] Game (phone), score dots hidden - "I don't know how many I have." On phones `.score-pill .slots { display: none }`, so the only progress is the text "0 / 10" or "1 / 10", which a pre-reader cannot read. Desktop and tablet keep 10 tiny circles (about 22 px / 16 px), which are also too small to count. Practice length is 10 holds x 3 s (still unchanged from earlier item 12). -> Fix: show a chunky star row or path that fills, even on phone, wrapping onto a second line if needed, with at least 28 px stars; keep the "n / 10" text small beside it.
8. [Major] Game, reward moment (phone 7) - "Did anything happen?" Completing 3 seconds changes the bar to light green with a small star icon and "Great job! +1 point!" and the score changes from "0 / 10" to "1 / 10" in a text pill. There is no flying star, confetti or character reaction visible in the screenshot (animation unverified; success chime not heard). The text and "+1" mean nothing to a pre-reader. Same as earlier item 7. -> Fix: when a hold completes, fly a large star from the ring to the score row and bounce the character (item 3). Keep the chime under the volume setting; no loud or flashing effects.
9. [Major] Game, Back button (all sizes) - "I pressed the arrow and everything vanished." The 48-52 px "←" button at the top-left exits instantly to Home (app.js `onBack`, no confirmation), losing the current hold and the practice or level progress. It sits at the very top corner, a spot hit by a child's grip or thumb on a phone or tablet, and by mashing. Hold-to-open protects Settings but not Back. -> Fix: either require a short press-and-hold (same widget as the gear) or a one-tap "Keep playing / Leave" confirmation with picture buttons (a house, a play triangle); keep it large but move it away from the corner hit zone, e.g. inset it. Do not change what progress is kept without a spec decision.
10. [Major] Home (phone 2, desktop 2), mode choice - "Which one do I press?" (carried over, earlier item 8). Practice and Adventure are words in white cards with a small icon each (a note, a flag); Adventure is a list of word rows ("First notes", "Five-note scale") and on phone it sits below the fold (the child must scroll to see any level). "What do you want to play today?" is a sentence. The Do / Ré / Mi tiles are great and "Start practice" is large, so a child can still succeed by pressing the big purple button, but cannot tell what they chose. -> Fix: add a big illustration to each card from the cover art (mic + one note for Practice, a path with stars for Adventure); show the Adventure "Play" as one big button for the current level, with level rows led by picture or star count; shorten adult copy to a small line.
11. [Minor] Game, "Try again" cue - "So close! Start the hold again." Added since the desktop review (new `Feedback.TRY_AGAIN`, icon "↺"), shown for 1.5 s after a hold of 1 s or more is lost in reset mode. It is kind in tone and gives the child a cue instead of a silent reset (partial improvement on earlier item 5). But "Start the hold again" is a long sentence, and "again" after effort may feel like a "you lost" for a 4-year-old; also the ring still empties to nothing (snap vs drain is unverified in motion). With the 150 ms grace period (unverified live), a 4-year-old's breath will still wobble. -> Fix: keep the rule; shorten to "So close! Again!" with a friendly icon and have the ring/stars drain slowly with a faint ghost of the earlier progress; flag to the product owner whether pause-and-keep should be the default for young players (spec/default decision; it is already a setting).
12. [Minor] Game, grown-up text at child size (phone 3-7) - "TARGET NOTE", "Written pitch · Horn in F", "Hold for 3 seconds" and "Hearing DO / C4" or "Listening..." in small grey text compete with the real cues for a child who cannot read them. "Hearing DO / C4" is jargon but useful for adults. -> Fix: dim or hide in a young-player mode; keep for grown-ups.
13. [Minor] Home (phone 2), locked levels - "Why are these broken?" Dashed rows with the word "Locked" (carried over, earlier item 16). -> Fix: soft silhouettes with a small padlock, no word, no dashed border.
14. [Minor] Cover, Start Game has no icon (carried over, earlier item 13). -> Fix: add a play triangle to the left of the label.
15. [Minor] Level summary (phone 9, desktop 9) - blank white card with a title, stars, and sentence; no character or confetti; "Amazing! All 3 stars (0 restarts)." uses the word "restarts" (jargon). For fewer stars the text is "Great playing! You had N restarts. Keep it to X or fewer to win all 3 stars." (starReason). Empty third star appearance was not captured (unverified). Buttons are text only (Home, Play again, Next level). Phone wraps the three buttons into two rows at ~48 px, which is fine. -> Fix: add the cover characters cheering, animate stars in one at a time, icons on buttons (house, circular arrow, arrow), and move the "restarts" sentence to a small adult line; for fewer than 3 stars show an unfilled star as a faint outline, never a dashed hole. Escalate to Major if a child reacts to the empty star in live testing.
16. [Minor] Settings hold-to-open on touch (widgets.js `makeHoldButton`, HOLD_MS 1000) - "I held the cog and the circle filled up." Works for an adult, but 1 second is short for a determined 4-year-old who rests a finger on a shiny gear; the gear sits 10 px from the score pill and is a 48-52 px circle in a corner. A tap or short press only shows a text toast "Hold to open settings", which a pre-reader can ignore (good) but an adult may miss on a phone. On release before 1 s the ring resets (good). Long-press context menu is suppressed (good). I did not see it operated. -> Fix: keep it, but make the hold longer (about 2 s, as a config value), add a second grown-up gesture on touch (e.g. two-finger hold or a simple sum), and make the gear smaller or lower-contrast than the Back button so the eye does not go there first.
17. [Minor] Sound - no spoken prompts yet (carried over, earlier item 15); the child hears only the chime and the reference tone (neither heard by me). Pre-readers get no "higher / lower / yes!" voice. -> Fix: optional offline voice clips, off by default, under the volume setting.
18. [Minor] Tablet portrait game (tablet 3-7, pre-fix) - the staff card shows a large mostly empty white area with a small staff in the middle and the note and ring about 90 px; this was fixed after capture and is unverified. -> Fix: verify the new portrait layout keeps the note/ring and the speaker button large; check again at 4:3 landscape.
19. [Minor] Home on desktop and tablet shows an "Horn in F" pill (hidden on phone): harmless, grown-up information.

**Would this child come back tomorrow?** Maybe. The cover is a genuine hook and the big Do / Ré / Mi tiles and speaker button give a child something to do and hear, but on a phone the first tap is hard and the permission prompt needs an adult, and after that there is no character, no big reward and no spoken help, so a 4-year-old will mainly be engaged by the grown-up. Items 1, 2, 3, 4, 6 and 8 move it to yes.

## Cross-age summary
Only the 3-5 band was reviewed in this pass, so the following is an expectation, not evidence for other bands.
- Issues likely shared with other bands: red far zones (item 5), small hold ring and score slots (items 4, 7), no friend or visible reward at the end (items 3, 8), Back exits without confirmation (item 9), mic-permission refusal help is text only (item 2; older children can read it but may still be stuck without a grown-up).
- Conflicts: 3-5 wants a large ring, a character, big star slots and a long hold on the gear; 12-15 may find a character and stars babyish. Recommended resolution (same as the earlier review): a "young player" presentation option (set by the grown-up in Settings, never in the child's path) that turns on the character, big star row and larger ring, while the compact tuner stays the default for older bands. The spec says a single profile (FR-25), so this must be a setting inside that profile, flagged to the product owner.
- Spec flags (not changed silently):
  - Section 6.1 (cover Start also asks for the microphone): the spec says the app "explains how to allow it and offers a retry" and never shows a failure state (FR-16). The web app complies in words, but the explanation is text only, which a 3-5 child cannot read; a picture-first or adult-directed presentation is a design addition, not a behaviour change.
  - FR-16 / FR-18: all gameplay messages comply in text. The new "So close! Start the hold again." (`Feedback.TRY_AGAIN`) is gentle, but "again" after effort may read as a miss to a young child; FR-18 asks for short positive messages, so shortening is within spec.
  - NFR-01 (100 ms): not testable from static screenshots; needle transition is 40 ms and the loop runs on `requestAnimationFrame`, but the 80-200 ms audio window latency was not measured. Unverified.
  - Reference tone, shorter practice goals (FR-16 / levels), and hold-pause default for young players would be new requirements or default changes for the product owner; I do not propose changing them silently.
  - Section 6.1 describes the web app as a Progressive Web App for phones and tablets, but the spec has no touch-target minimum; consider adding one (for example 48 px, 72 px for the cover Start) to the spec so item 1 cannot recur.
